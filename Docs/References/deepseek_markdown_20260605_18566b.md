# 动作游戏核心战斗系统设计文档

## 一、格挡与重攻击反馈

### 设计目标
- 格挡敌人的**重攻击**时，应给予更华丽的演出和更高的奖励。
- 避免频繁格挡普通攻击影响战斗节奏。

### 实现要求
- 为敌人的每一个攻击判定配置明确的标记：`轻攻击`、`重攻击`、`投技`等。
- 这些标记与技能伤害倍率、冲击力等数据一同存储在攻击配置中，用于伤害计算和动画表现。

### GAS 应用建议
- 利用 Unreal GAS 的 `EffectContext` 传递攻击类型、标记等信息，可在技能触发时判断是否为重攻击，进而触发特殊格挡表现。

## 二、战斗位移控制

### 设计目标
- 位移距离、位移时间作为攻击参数的一部分进行配置，使位移行为更可控。

### 物理实现
- 通常位移速度会随曲线衰减（非恒定加速度）。
- 若需要根据位移距离和位移时间准确计算初速度，**必须对速度衰减曲线进行积分**。

### 建议做法
- 配置位移曲线（如 `FloatCurve`），运行时根据曲线采样速度，而非直接使用匀速公式。

---

## 三、硬直、冲击力与输入缓冲

### 硬直与前后摇规范
- 对不同冲击力等级（轻、中、重、击飞等）的硬直时长做出明确数值规定。
- 敌人不同冲击力对应的**攻击前摇、后摇时间**也需规定，确保手感一致。

### 预输入缓冲（基础概念）
- 提供输入缓冲（Input Buffer）以保证连招和闪避的流畅度。
- 使用 Enhanced Input 系统提供的注入输入方法，通过 `AsyncTask` 将回调绑定到输入组件，可简单实现输入缓冲。

---

## 四、敌人追踪性能与走位设计

### 追踪策略参考
- **怪猎式**：敌人对特定方向的追踪能力更强，鼓励玩家往指定方向闪避。
- **法环式（女武神）**：极高的追踪性能，迫使玩家精确掌握翻滚时机。

### 设计原则
- 让**所有技能都可以通过纯走位规避**，这是重要的平衡标准。
- 纯走位可躲避 → 为高端玩家提供额外挑战，提升观赏性。

---

## 五、伤害计算与表现顺序（含处决）

### 一般规则
- **数据计算优先于表现**：先算出伤害、命中效果，再播放对应动画。

### 处决特例
- 处决流程：**总伤害预计算 → 确定表现（是否直接击杀） → 伤害延迟结算**。
- 大部分游戏简化处理：处决只造成一段伤害，即使动画中有多次攻击，也仅在最后一下结算。
- 只有确保能击杀敌人时，才播放“直接处决死亡”的华丽演出。

## 六、视角与角色旋转管理

### 正视角锁定
- 控制旋转与角色旋转保持一致，无需额外处理。

### 侧 45° 视角锁定
- 控制旋转与角色旋转不一致，需要**手动管理角色和控制旋转**。

### 手动管理的优势
- 锁定状态下按左右闪避，可保证闪避轨迹为**圆弧**而非直线。
- 避免玩家向左右闪避时反而移动到远离敌人的位置。

---

## 七、闪避系统与极限闪避

### 碰撞代理
- 闪避时在原地留下“碰撞代理”（如一个触发器），检测伤害来源。
- 这符合动作游戏玩家认知：从伤害区域移动到安全区域的过程中触发极限闪避。

### 极限闪避表现
- 镜头慢动作、特殊动画应**延迟一小段时间**播放。
- 目的：避免慢动作播放时武器正好穿过玩家模型，提升无敌帧的可信度。

---

## 八、攻击吸附与 Motion Warping

### 设计目标
- 即使要求玩家精确控制攻击距离，也需要适当的攻击吸附（Attack Magnetism）。

### Motion Warping 作用
- 让玩家角色自动接近目标。
- **控制动画的最佳释放距离**，避免玩家贴脸攻击导致动画穿模或别扭。

### 参数要求
- 设计师需精确配置：
  - 吸附最大/最小距离
  - 吸附落点
  - 吸附时间曲线
- 以保证玩家体验的一致性。

## 九、预输入缓冲系统实现细节

### 核心职责
预输入缓冲系统主要完成两件事：
1. **监听并缓存**玩家的按键输入信息。
2. 在**指定的可输入时刻**执行缓存的输入。

### 监听缓存的实现方式对比

| 方式 | 做法 | 优缺点 |
|------|------|--------|
| **C++** | 批量监听输入事件，统一存储到缓冲区 | 方便、集中管理，代码复用性强 |
| **蓝图** | 在输入事件节点（红色）处手动记录每个按键 | 逐个手动记录，复用性差，容易遗漏 |

> 推荐使用 C++ 实现通用的输入监听与缓存层。

### 执行缓存输入的方法

#### 方式一：Enhanced Input Subsystem 的 `InjectInput`
- 可注入一个虚拟输入，模拟玩家按键。
- **重要限制**：如果玩家当前已经**长按**了某个键（例如按住方向键或攻击键），则无法注入新的相同动作的输入。
  - 类比：注入输入就像一只机械臂帮你按键盘，但玩家自己的手指已经按住了那个键，机械臂再按就没效果了。

#### 方式二：专用 Input Action 资产（绕过长按阻塞）
- 为预输入注入创建**专用的 Input Action**，例如：
  - `IA_Jump` —— 玩家正常使用的跳跃。
  - `IA_Jump_ForInjection` —— 仅供预输入系统注入使用的跳跃。
- 两个 Action 都绑定到相同的 Gameplay 逻辑（如 `DoJump()`）。
- 当预输入需要执行跳跃时，触发 `IA_Jump_ForInjection`，由于玩家并未长按这个专用 Action，注入始终有效。

#### 方式三：输入中间层（推荐）
- 设计一个独立的**输入中间层**，负责：
  - 监听原始玩家输入。
  - 缓存输入请求。
  - 在适当时机向真正的 Gameplay 指令转发。
- 架构演变：
  - 旧流程：`输入事件 → 跳跃技能`
  - 新流程：`输入事件 → 输入中间层 → 跳跃技能`
- 中间层同时具备“监听+存储+执行”的能力，完全避开 Enhanced Input 注入的长按限制，且更易于扩展（支持连招序列、输入优先级等）。

### 最终建议
- 小团队或原型阶段可使用**专用 Input Action**方案快速验证。
- 正式项目中推荐实现**输入中间层**，以获得最干净的架构和最灵活的预输入控制。
